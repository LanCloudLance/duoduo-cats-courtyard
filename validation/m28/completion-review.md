# M28 全游戏内容与美术完成度独立审查

审查日期：2026-10-10。权威源码：`outputs/duoduo-game`。基线版本由主代理提供：M27 / `f244d27a7e5abbe78bd6a7f299fc2c85e820ea8e` / 私有 Site 18；本审查没有执行 Git、部署、GUI、正式存档或产品修改。实际依据是本轮读取的权威源码、资源元数据与已有渲染证据。资源快照和逐项缺口见同目录 `assets-completeness.json`。

## 结论

**当前是故事可闭合、规则已有实质改善的可玩实现，但还不能据此交付为完整成品。** 用户说“像 Demo、明显有素材没完成”有具体依据：重要剧情动作只有通用姿态，NPC 缺少剧情状态；机关复用的图形对象经常不符合所扮演的物件；多个故事地点压缩在同一张静态背景；主线通关仍被入口和尾声称为“试玩”。这些是内容生产、表现接入与成品组织共同的问题，不是再跑一遍测试能解决的。

不应否认已有工作：序章有可观察的门/地毯系统，第一章有空气与风向，第二章有可转移支撑和承重，第三章有反射、源高度与接收方向，第四章已有真正可比较的试光线路，第五章已有主动引光/维护轮/折枝解锁。保存、恢复、提示、记事也已接入。旧 M27 审计中“后两阶段纯计时”“两场战斗完全相同”“没有章内保存”等描述不能原样当成当前缺陷。

本次没有真实九岁儿童或两名独立玩家参与。以下儿童视角是代理评审假设，不能写成“儿童通过”。没有完整陌生玩家时长采样。原稿的 **175–230 分钟主线、4–5 小时含探索** 仍是设计预算；不能用脚本耗时、场景数量或测试数量证明达到预算，也不能反过来武断报一个实际游戏时长。

## 美术语言与几何应如何验收

保留暖木、旧铜、青绿光、绘本环境和现有三位主角风格。问题不在于手绘背景一定要变 3D，也不在于矢量特效不能用。当前半写实背景、厚轮廓角色、拼贴机制和工程示意线之间缺少统一的“能操作/已锁定/暂时有效”语言。

- **永久已修**：结构真实合上/撑牢、锁舌到位，收光后保持，不只靠绿色染色。
- **临时支持**：能看见受力或光供给的连续路径；撤掉后部件回到明确位置；安全回退看得懂。
- **携带物**：从原位移除，贴合角色手/口，落地可拾；装备获得以后角色外观与架子都改变。
- **调查对象**：有物理载体，发出试光才能出现结果；结果记录不应像开发 HUD 漂在地面。
- **前后遮挡**：角色从机关前后走过，脚点、互动热点、发力点不脱节；门的可见洞与通行尺寸吻合。
- **轮廓与比例**：不能为适配碰撞把整张镜子/门/机盖压扁成长条。允许适当适配，但用途变化应有专用形状。
- **文字**：留意默认顶部目标 1010×53、底部 1232×103，约占 1280×800 面积的 17.6%，再加角色名和机关标签。数字只是布局量，不是可读性结论。关键操作的形状和动画先可辨，再缩减常驻解释；提示按需。

M26 metadata bounds 全部合法只说明矩形在纹理内，不说明裁切准确、键色边缘干净、动画不跳、动作方向正确。原始 atlas 与运行时大小都要查。home front/rear 同帧属于明确缺帧/重用，需在四向移动观察中判断影响；不得用 adventure 的前后帧存在代替家中验收。

## 全游戏验收门槛与进度账本

上一版 `work/m27/loop-state.json` 同时写 `objective=complete-existing-five-chapter-game`、`status=complete`、`human_acceptance=false`，只用“tested scope 内无 P0/P1”收口。这种范围压缩会反复产生“程序完成而用户认为仍是 Demo”。新账本应把本轮目标定为整体成品，技术、内容表现、代理评审、真人/硬件验收分别记状态；不再用总百分比。

每条体验单元都记录：**承诺的玩家结果 → 当前可见行为 → 缺口 → 负责人 → 下一次关闭证据 → 技术状态 → 体验状态**。状态建议为 `未制作 / 已接入待看 / 正常输入已复现 / 代理审查退回 / 代理审查通过 / 待真人或硬件核验`。文件已生成、测试已通过、发布成功可以作为证据类型，不能直接把体验状态改成通过。

| 体验单元 | 当前应登记的状态 | 下一关闭证据 |
|---|---|---|
| 从入口开始连续到回家 | 技术主干存在，成品入口退回 | 新档正常入口单人全程；双人相同叙事顺序；中途退出后继续 |
| 序章家庭与发现门 | 规则已接入，表演待补 | 三种可选家庭互动、门谜题误操作、两位共同离开 |
| 第一章初次救助和据点 | 规则已接入，场景/休息待补 | 路→战斗→驿站→亮灯→真正坐下，同一顺序连续录像 |
| 第二章分工和信任 | 规则已接入，对象语义待补 | 支撑交接/错误卸载/恢复/桥后亲密反馈连续片段 |
| 第三章重逢和完整队伍 | 规则已接入，关键演出退回 | 重逢、装备、变式、主动撤光的正常输入和重试 |
| 第四章调查和选择 | 规则已接入，空间/角色表现退回 | 三个试验结果的可比较现场、修罩前后差异、留下帮忙的确认 |
| 第五章修复高潮 | 主動阶段已接入，机体状态待补 | 挡臂/错误引光/错误卸力/恢复/机体停止，音画和规则同一状态驱动 |
| 告别与家中尾声 | 事实闭合，成果与表演退回 | 路网回扣、赠礼、原房间/原沙发、装备归位、主动结束 |
| 可选发现和回访价值 | 原稿提案未形成内容承诺 | 先确定采用的短支路；若采用，完成/留存/重访三点联动 |
| 时长与理解度 | 未测量 | 陌生玩家分章耗时、卡点、提示层级、跳过/重读；不得虚报 3–4 小时 |

整体验收最低包括：

1. 所有必需叙事/玩法状态都有正确可见表现，无“台词说已做、画面没做”的主要缺口；没有关键物件用不相干道具临时代替。
2. 每章至少包含一次已学规则的变式或组合，错误选择可理解且可恢复；不靠加入更多热点和等待拉长时长。
3. 两位玩家能在每段合作中说明自己的贡献；单人自主切换仍可完成，安全随行不代解谜。
4. 连续主线、错误路径、章内暂停/退出/重开、已完成后回访均用正常输入验证；动态检查覆盖不同方向/状态，不能只用设置好的静态场景。
5. 序章、重逢、选择留下、路网点亮、回家这五个情绪节点在动画/声音/可读台词上完整，不被热点提示打断。
6. 键盘/Web、实际 PC 手柄、实际双人和真人儿童理解度的结果分列。缺少硬件或真人时可完成技术及代理闭环，最终写清“仍待该项”，不能假装用户已接受。
7. 先整合再发布；Git/source/package/部署读回一致是发布门槛，不能替代上述内容验收。

## 推荐制作顺序

**第一轮：确立成品入口和全章内容账本，同时处理主线表演接入、关键对话节奏、回家锚点。** 这些直接修正最强的 Demo 感，也能快速显示新方向。已有 social 图集先复用验证，明确不足再补图。

**第二轮：按功能补齐机关状态包，重做第四章舞台和第五章机体结构。** 保留已经验证的状态/恢复规则，让画面真正表达它们。每次修一个有玩家后果的缺口，并跑一条不同的正常输入路径。

**第三轮：做全章节奏、奖励与音景。** 明确要采用的短支路和家中留存，区别故事遭遇场地，补适量物件/环境/猫音，回扣已修世界。根据陌生玩家采样校准篇幅，不为达到分钟数灌水。

**最后：独立专业审查与儿童代理审查重新挑错，完成后才整理成品文案与发布回执。** “已修掉多少项”只用于追踪；主要结果应是哪个整段体验已从头到尾达到验收门槛。
