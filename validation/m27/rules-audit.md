# M27 独立规则与关卡审计

审计日期：2026-10-10。范围：权威源码 `outputs/duoduo-game` 的序章、第一至五章 state、共同交互层、关卡路由，以及庭院、光廊、风铃、战斗和休息 state 的相关规则。只读审计，无游戏、Git 或部署修改。

本报告采用 `intended-vs-implemented` 的意图与实现对照法。结论来自代码路径和设计稿，**没有把受控脚本通关、测试计数或部署成功作为陌生玩家理解、协作或乐趣的证明**。本轮没有真人盲测，体验后果是有具体机制依据的评审判断；下面分别给出结构验收和正常输入下的玩家验收。

原剧情稿自身声明部分新增内容是提案。因此，“既定底线的实装缺陷”与“稿中未制作内容”分开；本报告不把所有旧提案自动升级成必须做的新需求。用户当前确认的 PC 手柄、单人自主切换、同屏双人、战斗 AI 支持高于旧稿仍写“候选”的控制方式。

## 总判断

当前有完整的故事主干和大量可靠的局部状态保护，但后四章仍更接近可操作的剧情骨架。最主要问题不是缺少机关数量，而是：**机关的因果越来越被目标栏说出，玩家完成越来越多的指定角色点击；最终挑战后两阶段靠保持状态加计时完成。**

值得保留：第二章的承重和永久桥锁、第三章撤光后安全回台、第四章“破罩”与“回收机构”两个故障的区分、保留应急归途、第五章不伤害机器与猫、最终真实回家。不能因为审计发现深度不足而撤掉这些故事及恢复保障。

优先顺序：先修保存与操作可信度（1、2、8、9），再做第二至五章递进（4、5、3），再平衡单人/双人节奏（6、7），最后补关卡世界反馈和角色表演（10、11）。11 项不代表必须并行开 11 个系统；建议按下面的统一规则在同一条主线闭环。

## 1. 章节内的“进度保留”只在内存中，退出后需要从章首重做

- **分类 / 优先级：** 实装恢复缺陷，P1。
- **设计意图：** 剧情稿 286 行要求每阶段保留机械状态，353 行要求失误保持已完成机关；长章节设计预算为 30–55 分钟。
- **证据：** `game/story_chapter_base.gd:144–150` 的 `record()` 在 `finished == false` 时返回空字典，`restore()` 只接收 `completed == true`；`game/story_chapter_view.gd:58–79,108–113` 只在通关后保存。第五章 `stage_checkpoint` 虽在 178、293、303 行递增，却没有中途持久化路径。第一章也仅 `finished` 时保存（`chapter_one_state.gd:219–224`）。
- **触发 / 后果：** 玩家已完成第一处维修或第四章防风罩后关闭窗口、重载或改选章节，再回来恢复为章首。界面中“维修保留”容易被理解为可靠检查点，实际只覆盖当前进程内的小失误。
- **建议：** 以叙事安全点保存最小章内事实：永久桥锁、工具获得、已判明证据、已修阶段、所在安全区。读档以安全锚点重建人物和临时保持，不保存半空中、受击中或易失的计时状态。完成记录与进行中记录应区分。
- **结构验收：** 在每个永久里程碑之后，通过实际退出/重开验证恢复；不重复消耗、对话强制重播或再次战斗；损坏存档能退到最近可信安全点。
- **玩家验收：** 陌生玩家中途休息再回来，能从场景和一句摘要知道已做什么、下一件事是什么；无需解释“通关记录”和内存检查点的差异。

## 2. 最终战的举盾规则、机械臂画面和失败判定不一致

- **分类 / 优先级：** 实装规则与表现不一致，P1。
- **设计意图：** 稿 268、280、286、380 行要求用此前学会的工具，通过摆动预兆抵挡夹臂，失误可理解并重试。
- **证据：** 普通战斗 `battle_state.gd:159–183` 持续举盾可防御；`345–350` 的快速挡招提供更好的机会而不是让慢举盾失效。最终战 `chapter_five_state.gd:249–253,278–284` 却要求 `boss_clock - shield_started < 1.5`，否则早举盾也会被推走。失败判定取卡槽附近 140 像素或团团锁扣附近 110 像素，绘制预警弧半径仅 62（`386–390`）。机械臂尖端用另一套正弦位置（`370–374`）；到判定时刻 1.8 秒，尖端约为 `(745,390)`，与卡槽 `(700,505)` 相距约 123 像素，未接触卡槽就可能判失败。
- **触发 / 后果：** 玩家沿用前章提前举盾，或依据臂端判断站位，得到与已学规则和可见接触不符的失败。反馈只说再看预告，没有区分过早、方向错误、站位错误。
- **建议：** 一套共享攻击阶段驱动画面、声音、轨迹和接触判定。普通防御保住安全，正确时机才把臂送入卡槽；若必须要求时机，也应先做安全练习并清楚提示失败原因。预警覆盖真实危险区，判定发生在可见接触时刻。
- **结构验收：** 逐帧录制挡中、过早、晚挡、背向、站外 5 种情况，接触点和结果一致；角色在显示危险区外不被范围条件推走。
- **玩家验收：** 首次失败后玩家能指出“早了 / 朝向错了 / 站错了”，下一次有针对性改变动作；不能靠猜内部 `boss_clock` 的阈值。

## 3. 最终挑战第二、三阶段由主动维修退化为开关加等待

- **分类 / 优先级：** 已实装但核心体验不足，P1。
- **设计意图：** 稿 276–286 行明确“有动作压力的修复战”，圆圆第二阶段承担“持续主动操作”，第三阶段是分段转轮与拉枝。
- **证据：** `chapter_five_state.gd:181–197` 的引光、转轮、爪钩均是一次互动开关；`288–314` 中第二阶段只需正确保持 2.3 秒，第三阶段保持后每 0.9 秒自动拉出一段、共 3 段，最后测试再保持 3 秒。第二、三阶段没有新的危险周期、选路或需要判断的状态，重复分段没有改变玩家决策。
- **触发 / 后果：** 两人把角色送到指定点按互动后，可以同时放下手柄等阶段结束；单人同样只是按顺序设置开关。高潮的实际参与度低于第一阶段，也低于现有独立光廊。
- **建议：** 保持三个阶段和故事目标。阶段二让吸光口有可读的工作位置，圆圆选择缓冲座/方向、朵朵在被引走的间隙转轮；阶段三每个回位段改变受力方向或可用扣槽，玩家观察后重新分配动作。单人可把已经确定的简单任务锁定，避免要求三路同时精细操作；不把增长等候秒数当成难度。
- **结构验收：** 每阶段至少有一次“观察变化 → 选择行动 → 结果验证”；从任一初始正确站位开启保持后，不应全员零输入直接完成全部剩余维修。
- **玩家验收：** 通关后能说明每段为何换方向/松轮/换扣槽；能指出各角色怎样帮助另一位，而不仅说“按完等条满”。

## 4. 主线没有承接现有更成熟的解谜规则，第二、三章没有形成足够的递进

- **分类 / 优先级：** 既有系统的主线整合与关卡深度缺口，P1。
- **设计意图：** 稿 126、182–184、268 行要求先学协作，再组合以前的规则；历史批准方向也是观察、假设和验证。
- **证据：** 第二章存在真实的灯向加承重组合，不能说完全没有解谜；但两桥段仅分别要求 `lamp_a == 1`、`lamp_b == 2`（`chapter_two_state.gd:27–38,58–80`），每桥一次绞盘开关，后续爪钩为三个顺序单点。第三章 `95–117,135–137` 再次采用固定灯向、拨扣、固定板向，最后出口只需面向上方。常驻目标直接给角色与操作顺序（`chapter_three_state.gd:153–166`），第五章目标甚至给出箭头式操作答案（`chapter_five_state.gd:124–148`）。
- **对照可复用资产：** `light_state.gd:43–79,119–135` 已有单枚桥扣复用、承重限制、蓄光记忆；`chime_state.gd:56–96,101–131` 已有反射/分光、源高度和接收方向。这些不是新提案。但 `ui/lobby.gd:133–149` 将光廊/风铃接在独立庭院流程；故事从第一章直接到第二章（`104–107`），所以完整故事没有这些更成熟的推理段。
- **触发 / 后果：** 玩家学到“每个道具各按一次、方向试四次”即可推进，而非用已知规则解决新布局。程序有了更强谜题，不等于主线玩家已体验到。
- **建议：** 用既有系统的核心规则改造现有桥、钟楼和树心，不增加世界地图。第二章承重教学后加一个必须回收/换用的支撑；第三章让相同的照明与反射规则在新位置组合，并允许错误假设得到可见结果。常驻目标只说要解决的现场问题，观察提示、规则提示、具体方案分三级按需给出。
- **结构验收：** 去掉目标栏操作答案仍有完整可见证据链；至少一个后续机关不能靠保持前一个最优配置直接通过，且新解法只用已教学规则。
- **玩家验收：** 先让玩家说下一步预期会发生什么，再操作验证；首次碰到变式时能迁移规则。记录无提示理解率、提示层级和卡住原因，不用最短脚本耗时评判深度。

## 5. 第四章的真相目前由三次角色点击宣布，玩家没有亲自验证因果

- **分类 / 优先级：** 已实装剧情成立，调查玩法未成熟，P1。
- **设计意图：** 稿 223–231 行要求圆圆照见、团团发现、朵朵串起证据，237–239 行用修罩后仍回流验证两个故障不同。
- **证据：** `chapter_four_state.gd:114–132` 依次设置 `duct_seen`、`branch_seen`、`arrows_seen`；角色和前置布尔值满足后，互动直接说出全部结论。`收送试光柄` 不是可比较的收/送控制，调查阶段一次按键就宣布“箭头停在收”，修罩后再按一次必定宣布仍然倒流。没有让玩家尝试一个有可观察结果的假设。
- **触发 / 后果：** 玩家只知道该换哪只猫、找哪个热点；即使完全没理解风罩与回收机的差别，也能按任务顺序推进并“查明真相”。
- **建议：** 保留现有真相。使试光柄能实际选择小范围收/送，让未修罩时的外泄、修罩后的回流有区别；圆圆照亮线段、团团标出卡住的构件，朵朵用试送结果确认。错误测试只损失短时间，不损失任务道具或退路；不用答题对话框替代现场推理。
- **结构验收：** 能演示两种不同故障现象、修罩前后同一操作的不同结果；跳过某证据也不会凭一次点击自动获得所有知识。
- **玩家验收：** 在提供应急灯匣前，询问玩家“外罩已修好，为什么还不能回家”，答案能联系亲眼看到的回流与卡扣，不只是复述刚出现的台词。

## 6. 三角色有必要的技能门槛，但双人常呈串行交接，朵朵玩家缺少持续参与

- **分类 / 优先级：** 双人节奏与角色贡献缺陷，P1。
- **设计意图：** 稿 126 行不让一人长时间等另一人；280–284 行要求双方移动、观察与操作。支持单人意味着“需要两个人同时在线”不是目标，三角色贡献和双人协作价值才是目标。
- **证据：** 第四章取灯罩必须团团拉环 → 圆圆定光 → 团团进去取回 → 朵朵最后接住（`chapter_four_state.gd:89–103`）；调查是圆圆 → 团团 → 朵朵（`114–129`）；修罩是朵朵进入无限保持，团团一次拉扣，圆圆一次照亮，再朵朵点击（`133–150`）。第五章圆圆设置后切团团，而朵朵维持轮的按钮无需继续操作（`chapter_five_state.gd:186–197,297–305`）。
- **触发 / 后果：** P2 在两只猫之间承担多个步骤，P1 到位后主要等待。角色限制提供了“必须换人”的门槛，却没有充分提供两人沟通、一起判断或相互改变局势的理由。
- **建议：** 保留固定角色。让朵朵控制可见的承重/线路选择，猫玩家带来另一侧信息或具体操作，两方结果相互可见；将长串行段拆成可并行准备的短循环。已经学会的保持允许单人锁定，双人则能更流畅地分工。不要为了证明合作而强塞不可单人完成的同步按钮。
- **结构验收：** 为每个合作段列出 P1、P2 的“观察/决策/动作/等待”时间线；连续长段不应只有一方有意义的操作。角色专属能力的结果必须改变另一方当前能做的事。
- **玩家验收：** 双人正常试玩记录每人的无事可做时段，并访谈是否知道伙伴正在帮自己什么；“两人都按过 A”不算合作成立。

## 7. 单人在解谜完成后还要反复逐个搬运角色，安全归队没有主线实现

- **分类 / 优先级：** 单人节奏与恢复缺陷，P1。
- **设计意图：** 单人解谜由玩家自主切换；稿 353 行同时要求完成通路后安全归队、可召回，自动猫不代解谜（355 行）。这允许完成之后的安全通行辅助。
- **证据：** `story_chapter_base.gd:65–80` 单人只移动当前角色，没有非受控角色跟随；永久路寻路只用于双人的第三只猫。`exit_gather():44–50` 却要求全员进入 130 像素圈。第二章窗边、第三章地图、第四章应急门/休息桌、第五章维护门/升降台/归途门/水盆/沙发均反复要求全队就位。第五章还在所有修复阶段禁用第三只猫跟随（`chapter_five_state.gd:79–81`）。
- **触发 / 后果：** 推理已完成后，单人重复走相同安全路径两三遍；家中水盆与沙发也变成集合搬运任务，削弱结尾轻松感。若玩家不知道另一只猫留在何处，就把操作摩擦误认成谜题没解开。
- **建议：** 增加明确的“安全归队”行为，只使用永久通路、不经过临时光路、不触发机关，且先提示会解除哪些可解除保持。也可以在跨区确认时由人物沿已解锁路径实际走到集合点。保持中的关键角色不得擅自移动。
- **结构验收：** 角色停在旧机关后，主角到出口可一次召回；无穿墙、无替解谜、无跨未修桥。无法安全召回时标出具体伙伴与阻断点。
- **玩家验收：** 单人从修复完成到下一叙事点的主要时间花在前进，不花在重复搬运；仍能随时自行切换和摆放解谜角色。

## 8. 同一个“工具键”和保持/取消动作跨章节变义，玩家无法迁移操作

- **分类 / 优先级：** 交互语言缺陷，P1。
- **设计意图：** 稿 268、286 行要求最终关卡沿用已学工具；353 行要求保持可明确完成或取消。
- **证据：** `story_chapter_view.gd:99–104,135–138` 始终显示右肩/R 为“工具”。但第二章未覆盖 `tool`，实际调用 base `137` 变成提示；第三章工具只在特定圆圆状态收光，否则变提示（`chapter_three_state.gd:131–134`）；第四章任何角色工具直接等于互动（`chapter_four_state.gd:185–186`）；第五章仅猫在热点工具等于互动，其他情况是提示（`chapter_five_state.gd:255–257`）。第四章定光重复互动不会解除、移动才会停；第三/五章相同观感的光则可再次按互动切换。
- **触发 / 后果：** 玩家学会按工具后，下章可能突然得到答案而没执行动作；想取消保持却重复触发台词。提示、工具、取消三种意图被一个键按章节条件混在一起，键位说明没有解释当前实际动作。
- **建议：** 全主线固定：互动是身边物件动作；工具是角色工具的明确上下文动作；想一想单独请求提示；保持的开始、继续、解除使用相同语义并有场上标识。若工具没有可用目标，显示工具状态/范围，不自动泄露谜底。
- **结构验收：** 同一输入状态表覆盖全部章节、键盘和手柄；逐章验证持有、换角、移动、取消、暂停、恢复，没有同一动作意图因章节改变而变成提示。
- **玩家验收：** 学过一次定光后，后章无需重新解释就能开始、换猫继续、回来收光；不通过试按一排按钮找取消键。

## 9. 关键剧情只有一个可覆盖的限时文本槽，因果与角色选择容易丢失

- **分类 / 优先级：** 叙事交互缺陷，P1。
- **设计意图：** 稿 44 行逐步解释世界规则；第四章主动选择、第五章阿灯共同改变是主线因果，不是可有可无的提示。
- **证据：** base `say():39–40` 每次直接替换 `message`，统一 8 秒；view `133` 到时清空，无历史或确认。四章 `109` 在一条长句里包含暴风、回收、停止杆、小门来源四件信息，`155` 又把朵朵决定、留灯匣、阿灯行动塞在一条信息。后续随便互动或请求提示即可覆盖。接近目标的短物件反馈与关键剧情共用同一优先级。
- **触发 / 后果：** 玩家边操作边阅读，伙伴随手按一次工具/互动就把解释覆盖；之后知道去哪但不知道为何。故事上的主动决定成为按掉的一段说明，难以形成情绪转折。
- **建议：** 关键剧情分成少量短句，由玩家确认推进并能重读；普通机关反馈保持短暂且不抢占关键句。双人需要清楚是谁确认、另一位是否仍可活动；不要用长自动倒计时制造节奏。
- **结构验收：** 同一帧/短时间内提示与关键剧情触发，关键文本不丢；暂停、切角、手柄断连恢复后保留当前句；可找回已经看过的因果信息。
- **玩家验收：** 不读攻略也能在第四章后说明小门为何出现、为什么不能只修罩、为何保留应急灯匣；允许按自己阅读速度停留。

## 10. 看得见的机关经常因隐形章节阶段而完全不可互动

- **分类 / 优先级：** 世界与反馈一致性缺陷，P2。
- **设计意图：** 稿 44、225–239 行要求用场景和物件变化解释规则，探索是观察现场，不是寻找看不见的事件旗标。
- **证据：** 第四章 `target():62–81` 用 `phase` 令大量物件只在某一阶段返回热点；`interact():86` 空目标直接返回。与此同时 `draw_world():203–260` 从一开始就绘制阿灯、暗槽、试光柄、破罩、扣子、休息桌。玩家先走到任何可见后续物件，会得到没有提示、没有查看动作的沉默。第五章也用 `target():86–122` 完全切换热点，绘制时不少物件持续存在。
- **触发 / 后果：** 场景允许走过去，玩家看见明显可操作物件却没有任何反应；容易怀疑站位或按键错，而非知道缺少什么条件。探索被压成按指定热点顺序跑图。
- **建议：** 显示物件就允许简短观察；不可操作要有世界内原因，如仍承重、没有接光、盖未开。后续区域若确实不可接近，用真实通路与镜头分区。已完成物件也应反馈“已锁稳”，不要凭阶段消失互动性。
- **结构验收：** 对每个可见主线物件枚举未解锁/当前/已完成状态，均有一致可读回应；没有必须等隐藏 `phase` 才突然活过来的普通道具。
- **玩家验收：** 玩家尝试提前检查机关时，能知道限制来自哪里，之后条件变了会主动回来。

## 11. 三角色的关键性格多留在台词里，主线完成事件没有相应可见互动

- **分类 / 优先级：** 身份表达与原设计表现缺口，P2。
- **设计意图：** 角色设定与稿 21–27、134–144、166–170、247–252、327 行：朵朵认真后放松；团团聪明且黏人、舔手玩爪；圆圆稳、被揉放松，不做随机操作惩罚。
- **证据：** 第二章完成桥时写“团团蹭她的手”（`chapter_two_state.gd:78`），实际仍沿用 `56` 的单角色 inspect 动作；第三章重逢 `90–91` 直接设置入队/位置并用一句话交代检查爪子和拥抱，没有相应两猫动作阶段；第五章摸猫 `240` 只调用朵朵 `act(0,"pet")`，文字同时描述团团舔手和圆圆送脸，却没有分别触发猫反应。view `123–131` 多种动作映射为同一个 reach/inspect。相较之下，序章 `prologue_state.gd:104–109,164–169` 确实同时触发伙伴回应，可以保留扩展。
- **触发 / 后果：** 外形和工具不同，但在最重要的重逢、庆祝与回家时，角色关系要靠读说明想象。“团团聪明”常等于可通过 role==1 的门槛，“圆圆稳定”常等于放置灯源，缺少让玩家感到这些是自己两只猫的可见反馈。
- **建议：** 只补少量高价值、可辨识的关系动作：团团观察后回看朵朵、完成后短暂主动靠近；圆圆被揉后安静摊开、维持任务可靠且不离岗；朵朵完成认真检查后才放松。动作由明确事件触发，短且可跳过；绝不把性格变成输入延迟或随机失误。
- **结构验收：** 重逢、桥完成、家中摸猫三个节点，动作参与者、朝向、距离与台词一致，不能隔屏“蹭手”；两猫在相同触发下有不同且符合设定的反应。
- **玩家验收：** 静音且隐藏名字/剧情字幕仍能从互动辨认团团的黏人和圆圆的稳定；无需只凭毛色和说明文判断性格。

## 统一设计语言：保留这一个小世界，形成可迁移的六条规则

1. **光只负责让东西可见或接通能量。** 先看到连续光路、接收面的朝向和受光变化，才能解释机关为何有效。临时照明消失后可见踏板消失；已经机械锁住的通路永久保留，形状/声音清楚不同。
2. **承重和固定必须有物理因果。** 朵朵托住、团团拆扣、支撑物代替人、永久扣落位的状态一眼能区分。一个支撑何时能拿走，由当前重量决定，不由章节旗标决定。
3. **团团做“发现与精细操作”，圆圆做“稳定与选择光路”，朵朵做“布置与确认”。** 团团不是通用钥匙，圆圆不是只站岗，朵朵不是队伍的搬运工。每章都要有一次角色改变另一角色可行行动的合作。
4. **互动、工具、提示、保持分工一致。** 物件显示现在会发生的动词；任务标题说问题，提示由观察到规则再到方案逐层给。操作结果先由物件变化表达，短文字补足。
5. **失败教会一件事。** 撤光、承重未卸、朝向偏离、时机早晚各有不同反馈。就近回台、永久成果保留；存档也遵循同一承诺。
6. **关卡按“教学一次 → 改变一个条件 → 组合两条规则 → 安全歇息”递进。** 不用把同一个方向机关复制两次来增长篇幅，也不靠更长计时冒充复杂度。最终修复考查旧规则组合，剧情后果在世界中可见。

可行主线递进（属于建议，不修改故事）：

| 段落 | 学到的关系 | 下一段需要迁移的知识 |
|---|---|---|
| 家中门 / 第一章枝架 | 压力使物件卡住；临时撑住可让伙伴处理 | 支撑物能代替人物保持 |
| 第二章运输桥 | 光路和承重是两条条件；锁扣使通路永久 | 已用支撑如何安全回收，再用到后一段 |
| 第三章钟楼 | 稳定光源、反射方向、猫的低道各有作用 | 用同一光源选择另一条路线；先固定再收光 |
| 第四章灯树 | 同一次试送在修罩前后有不同结果 | 区分外泄和回流，证实回收机构仍卡住 |
| 第五章树心 | 安全挡停、引开、卸力、拉扣综合 | 每次改变一个机械条件，再判断下一步 |

## 大循环验收建议

- **第一轮：可信。** 正常手柄/键盘验证逐章保存恢复、状态取消、最终战画面判定；错误输入有一致回应。能完成只通过这一层。
- **第二轮：理解。** 不知道解法的单人和一组双人，分别完整走第二至五章；评审不报坐标、不读内部状态，不主动解释谜底。记录观察、假设、尝试、结果和提示请求。玩家能通关但不能解释关键因果，仍未通过。
- **第三轮：参与。** 复看双方行动时间线、切换次数、完成后重复跑动、无事等待；修订角色分工与安全归队。单人困难不能靠解谜 AI 代解，双人平衡不能靠两人同步门槛挤压单人。
- **第四轮：故事与角色。** 关键转折由玩家自己的节奏读完；在重逢、修复、回家三个节点确实看到三位的不同反应。故事因果和角色身份均能被复述，才考虑高完成度交付。

现有测试仍有价值，但边界要明确：`tests/m25_five_playthrough_test.gd:8–76` 直接访问正确目标常量、精确朝向并观察内部阶段；`24–27` 还读取 `boss_clock` 决定举盾时机。它证明给定答案能通过正常输入路径，不能证明陌生玩家从画面发现答案。修订后的验收应同时保留技术回归与上述人类理解证据。
