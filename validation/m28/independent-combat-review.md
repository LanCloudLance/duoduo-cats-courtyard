# M28 普通战斗独立反驳审查

审查日期：2026-10-11。身份：非战斗实现作者的独立设计/代码审查。审查基于当时 `outputs/duoduo-game`，不是旧 M27。只写本报告与独立 QA 文件，没有改产品、正式存档、Git 或部署，没有开启 GUI。

**结论：当前证据未发现战斗内 P0/P1 阻断，但有三项可复现 P2 和一个尚未解决的设计反例。SOLO 控制归属比旧版明确；这不证明已经有手感或值得玩。前两类遭遇仍可能被朵朵的追击连按消耗掉，硬壳场才真正否定同一策略。实际连续渲染、声音、两真人和初见儿童仍未在本审查得到验证。**

根代理要求本轮先交静态/隔离报告、释放槽位给作者修复，因此这里不等待或冒充后续渲染审查。下列缺陷均已直接发根代理及战斗作者；主线段断点与旧 AI 文案由根代理接手。

## 1. 可复现发现

### P2-01：精挡没有兑现比提前持盾更长的主线开口

- 位置：`game/battle_state.gd:298–303`；约定来自 `work/m28/combat-review.md` 4.2 的“前 0.18 秒精确格挡产生更长但有界的开口”。
- 复现：SOLO 朵朵面向右，硬壳从右向左冲锋；分别提前持盾 0.05 秒和 1 秒，再推进同样 0.05 秒冲锋。
- 实测：两次 HP 都是 3，敌人同为 `exposed`，剩余开口同为 `3.18333333333333`；只有 `parry` 与 `guard` 反馈不同。
- 原因：主线 `armored` 的盾开口始终 `2.4 + SOLO 0.8`。只有未列入主线的 `elder` 根据 `guard_age` 改时长。
- 影响：主动冒险精挡没有可归因的机会收益，提前一直持盾更稳；画面若强调成功精挡，会承诺不存在的操作回报。
- 建议：在保持迟挡可靠的前提下兑现有界时长差；用同一冲锋、同一后续输入比较可多做什么。不能只增加闪光或伤害数字证明兑现。

### P2-02：出口确认后还要再按一次，完成态未提示这一输入

- 位置：`game/arena.gd:110–112,197–198`；`game/battle_state.gd` 的 clear→complete 分支。
- 复现：两段清完，站到出口按 A/E。
- 实测：第一次按键 `outcome=complete`，`next_level_requested` 次数仍为 0；提示只剩“小路清开了。”。再按一次才发出 1 次返回信号。
- 影响：初见玩家已按照出口提示完成动作，角色又不能移动，可能把停在完成画面理解为流程断了。它可以再按恢复，所以不列软锁 P1。
- 建议：若保留完整结果停顿，明确显示继续返回的键；或把最后一位出口确认与返回合同对齐。DUAL 应验证两人谁负责最后继续，避免一个人仍在等另一人。

### P2-03：猫角色技在普攻恢复尾部输入会静默丢弃

- 位置：`game/battle_attacks.gd:52–66`，对比 `press()` 的单格普攻缓冲。
- 复现：团团近身普通爪击后推进 0.18 秒，再按角色技，继续 0.30 秒；用同一状态将角色技换成普攻作对照。
- 实测：普攻对照实际补一击，目标 HP 从 4 到 3；角色技路径仍是 `claw`、目标 HP 为 4、`signature_cooldown=0`，技能没有启动，也没有拒绝反馈。
- 影响：玩家在刚刚命中后想接一次打断，和按普攻获得的容错不一致。按得略早的孩子只能多次试按，不知道是冷却、恢复还是自己没有按到。圆圆开始蓄力也走同一 `available` 拒绝分支。
- 建议：在末段恢复给予有界、单格、按实例归属的角色技意图，或明确表现拒绝原因；必须保留换人/失焦/暂停清队列及旧释放不落到新角色的边界。此处不建议堆叠长指令队列。

## 2. “仍然无聊吗”的设计反例

额外驾驶器只寻最近敌、借位置信息导航到近身、每 0.2 秒尝试普攻。它完全不读敌人前摇状态、不闪避、不用角色技、不换人、不为了硬壳主动绕背。用状态位置代替视觉和自动导航仍是强能力，因此它不是儿童模拟、不是随机乱按，也不是实际游玩时间。它仅用于否证“前两场必须做战术取舍”。

| 场地 | 角色 | 两段结果 | 模拟秒数 | 承伤 |
| --- | --- | --- | ---: | ---: |
| first | 朵朵 | 清完 | 9.0 | 1 |
| first | 团团 | 清完 | 11.3 | 2 |
| shell | 朵朵 | 清完 | 10.0 | 2 |
| shell | 团团 | 第二段失败 | 8.5 | 3 |
| shell | 圆圆 | 第二段失败 | 11.1 | 3 |
| reserve | 三位分别坚持一角 | 都在第二段失败 | 10.2 / 10.2 / 10.3 | 各 3 |

专业判断：first 允许普通连按成功可以承担入门容错；但 shell 原定让玩家比较“接前排冲锋或追后排封路者”，朵朵仍用同一个最近目标策略快速清完。布局有差异，不自动等于决定有差异。朵朵同时拥有较长普攻触达、扇形多目标、三连效率和盾，放弃猫的角色技在这条路径没有显著代价。这个样本不足以证明朵朵对所有技能打法全面最优，却足以要求一次有意识的 shell 再设计/试玩判断。

不建议通过加血或延长前后摇把 10 秒拖成 60 秒。更有效的验收是：同一角色同样技术水平，用不同目标顺序产生可看懂的安全/绕路/救援差别，并让一个错误优先级也有可恢复结果。无需强制使用技能，更无需角色颜色钥匙。

reserve 否定无脑策略，说明不能把整套 M28 全盘说成只有按按钮。它有引朝向、背面开口及两侧通路的真实规则；问题是这些规则能否由运动画面而非读代码被玩家学会。当前证据尚未回答。

## 4. 明确模拟 9 岁初见玩家视角

以下是设计推演，不是采访、真人玩测或模型代替儿童验收：

1. “我用朵朵跑过去按 F 就赢了。”——first 的容错合理；到 shell 若仍然如此，孩子可能继续只用熟悉角色，读不到另外两位的价值。
2. “我刚打到他，按 G 怎么没扑？”——恢复尾部的沉默拒绝会被归因为按钮不灵，而不是自己选择时机太早；这正与用户此前否定手感的原因相冲突。
3. “一直举盾也一样，为什么要等最后才按？”——当前精挡没有额外开口，孩子的推断是合理的。
4. “已经说路开了，怎么不回去？”——出口额外一次按键缺提示；可自行尝试解决，但不应把试按钮当作内容。
5. “硬壳怎么都不掉血？”——代码可解不代表可见。必须从实际动作画面确认：撞桩、停住、背部展开、正面弹回四个状态足够区分；此项保留到根代理渲染检查。
