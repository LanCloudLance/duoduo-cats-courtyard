# M21 Game Loop Implementation Plan

> For agentic workers: use superpowers:executing-plans in this session. Review the whole change in a separate pass after integration.

**Goal:** 修复试玩的单调、拥挤和机械操作，交付可验证的下一版并完成两种视角评审及修正。

**Architecture:** 原有 Godot 场景和状态为核心；音乐独立控制，战斗空间／种球／地带由状态驱动，风铃门是灯廊与休息之间的场景。源项目仍位于 outputs/duoduo-game，网页仓库保存源码及验证快照。

**Tech Stack:** Godot 4.7.2 / GDScript、Python NumPy / FFmpeg 原创音乐、Sites 静态网页。

**Spec:** ../specs/2026-10-02-m21-game-loop.md

## Global Constraints

- 原图保留；不复制名作音频、旋律、角色或关卡。
- 实际移动 FIELD 为 Rect2(-120,170,1520,650)；同屏两位可见，最多四敌人。
- 暂停、失焦、重试、存档与单人手动解谜保留。
- 托管每个文件不超过 25 MiB；保留原有网站访问范围。
- 儿童角度只作模拟评审，Windows 实体手柄不得以合成测试冒充。

## Review Focus

1. 切换／暂停时音乐叠加或重复从头播放。
2. 场地变大但敌人变成无压力追逐，或角色头部在 HUD 后面。
3. 同一次攻击重复击飞种球；种球／地带制造连续必吃伤害。
4. 风铃假亮、循环光路不停、白猫移动后仍保留旧解法。
5. 旧旅程安全点与新关卡转场冲突，原测试靠瞬移或直接置完成绕过新流程。
